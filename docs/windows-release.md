# Releasing I Need Air for Windows

## What users receive

Ship the MSI generated by `scripts\package-windows.ps1`. It contains the JavaFX desktop application and its own Java runtime. End users do not need Java, Maven, Docker, or Ollama to use I Need Air.

User data is stored outside the installation folder at:

```text
%LOCALAPPDATA%\I Need Air\data\i-need-air.db
```

This preserves favourites and cached place data across upgrades. For a portable or test installation, set `INEEDAIR_DATA_DIR` before starting the app.

## Build a release

1. Install a JDK that includes `jpackage` (JDK 21 or later).
2. Install WiX Toolset 3.x and ensure `candle.exe` and `light.exe` are on `PATH`. WiX is needed only to make MSI installers.
3. From the project folder, run:

   ```powershell
   .\scripts\package-windows.ps1
   ```

4. Test the MSI from `target\installer` on a Windows account that has not run the development version.

For a quick native-app smoke test without WiX, use:

```powershell
.\scripts\package-windows.ps1 -Type app-image
```

The executable will be under `target\installer\I Need Air\I Need Air.exe`.

## Optional local AI

I Need Air must not bundle an Ollama model: models are large, user-selectable, and updated independently. The app falls back to its built-in planner when Ollama is unavailable.

Users who want local AI itineraries can install Ollama from [ollama.com/download](https://ollama.com/download), then run:

```powershell
ollama pull llama3.2
```

Ollama normally starts its local service automatically. If it does not, the user can start it with `ollama serve`.

## Distribution and trust

Upload the tested MSI and its SHA-256 checksum to a GitHub Release or your private release page. Before distributing broadly, sign the installer with an Authenticode code-signing certificate; unsigned installers may show Windows SmartScreen warnings.

Docker is not used for the JavaFX desktop installer. If a future version adds a cloud backend for accounts, sync, or server-side AI, containerize that backend separately. Kubernetes is appropriate only after there is meaningful multi-user traffic and operational need.
